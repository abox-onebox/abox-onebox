四、本轮标出的「未测 / 缺口」风险清单

✅ 已补
券/余额全额覆盖分支（payAmount=0 不唤起微信）：order.service.ts:361-366。当用户券+余额恰好抵满订单总额时，系统直接置 PAID、不调微信——此分支此前三套 e2e 均无断言。本轮已在 e2e-coupon-blindbox.mjs 场景⑨ 实测：发面额=总额券→下单→断言 discountAmountFen=总额 / payAmountFen=0 / status=paid / 券核销，30/30 全过。该 🔴 缺口已闭合。
🟡 待补
团长退出 quit / 账户注销 cancel / 团长提现 withdraw / 协议 agreement：后端路由齐全且 e2e 中有提及，但本轮未逐一读其断言，属"部分测"。建议补针对性 e2e 或确认现有断言已覆盖主流程。
🟡 待补
邀请落地页 /leader/invite/:leaderCode：后端控制器存在、前端 fetchInviteLanding 接线正确，但 e2e 仅在 m2 提及、未确认有完整断言。免登录只读页，建议补一条"用团长码拉落地信息"的断言。
🔴 已知
POST /me/subscribe（上报订阅消息授权结果）：代码注释明确"未实装"（需新表、一期无法验证）。前端已调用 /me/subscribe/templates（GET，已实装），但上报动作无后端实现——这是设计缺口而非回归 bug，前端目前不会报错（上报被静默丢弃）。
🟡 观察
配送地图 / 异常单 admin 视图：路由存在、m3 覆盖订单中心异常单，但配送专属逻辑未细读断言。属低风险的后台展示，建议后续补。
