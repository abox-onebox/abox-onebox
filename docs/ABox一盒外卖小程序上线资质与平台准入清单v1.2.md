# ABox 一盒 · 自营路线 · 上线资质与准入执行清单 v1.2

> **文档性质**：上线前置条件的执行清单，非法律意见。审核规则以微信公众平台、北京市通信管理局、北京市市场监督管理局的实际口径为准。
> **编制日期**：2026-09-16 ｜ **主体**：北京巡礼之年科技有限公司（昌平区）｜ **品牌**：ABox 一盒
> **本版说明**：项目负责人于 2026-09-16 裁定 **回归「单主体自营 + 半成品供应链」路线**。本版取代 v1.1（第三方平台路线）的全部结论，并撤回 v1.1 引入的 EDI / 电商收付通 / 平台备案三项前置。
> **⚠️ 本版最重要的三个结论**：
> 1. **路线回到自营** —— ABox 是唯一对外经营者（向用户销售），4 家供应商仅提供**半成品**（B2B 采购关系），不再作为「入驻商户」。**《网络食品交易第三方平台备案》不再需要 → EDI 许可证不再需要**（EDI 是平台备案的法定前置）。
> 2. **资金定性恢复为自营 → 不涉二清** —— 供应商款属**采购付款**、团长佣金属**营销费用**，非支付结算业务；**不需要**微信「电商收付通」、不需要开二级商户号。⚠️ 该结论以「ABox 自主定价、自主销售、自担库存与食安责任」为前提，法务意见书须与此一致。
> 3. **123 号令仍须守住内核** —— 不冲突不等于免义务：ABox 自己的经营场所必须**实体门店 + 证照地址 = 线上店铺地址 = 实际出餐地址 + 网店名 = 门面招牌名**，且**禁止异地代工出餐**。半成品供应链模式下，「4 家供应商各出一菜、集散拼一份」的形态**只在供应商侧不承担出餐责任时才成立**，见 §四。

## 二、资金合规（恢复自营论证链）

**论证链**：ABox 向供应商**采购半成品**（采购付款，B2B 对公转账）→ ABox 完成加热/拼装/打包后**以 ABox 品牌销售**给终端用户（自有销售收入）→ 团长佣金是 ABox 的**营销费用**。

- 供应商 / 集散款项 = **采购付款**，非支付结算业务 → **不构成二清**
- 团长佣金 = **营销费用**（自有支出）→ **不构成二清**；个税走灵活用工平台代扣代缴（C11）
- **不需要**：电商收付通、二级商户号、商家转账洗白代收清算

> ⚠️ **前提条件（任一破坏则本论证失效）**：① ABox 自主定价、自主销售（不是替供应商卖）；② ABox 自担库存风险与食品安全责任；③ 款项关系是「采购」而非「代收代付+事后分账」；④ 不做多商家入驻形态。
> **行动**：法务出具《自营模式定性意见书》，逐条确认上述四点（取代 v1.1 要求重做的资金合规意见书）。

## 三、《食品经营许可证》是本路线唯一的长周期项

| 要素 | 要求 | 对 ABox 的影响 |
| --- | --- | --- |
| 经营场所 | 商用性质、可现场核查、有**食品处理区**（粗加工/烹饪/备餐/洗消分区） | ⚠️ 「**复用合作供应商场地、场地费 ¥0**」的旧口径**必须废止** —— 拿证主体须是 ABox，场所须在 ABox 名下（自有或长租） |
| 业态与项目 | 「**热食类食品制售**」（本项目须含"制售"而非仅"销售"） | 若仅购半成品**直接分装不加热**，可能只够「食品销售」；**要出热餐就必须有制售项** |
| 布局与流程 | 与申报一致的设备布局、专间/专区、冷藏冷冻设施 | 需按图施工后再申报，别先装修后补材料 |
| 人员 | 食品安全管理员 + 从业人员健康证 | 与 §一 第 10 项的食安制度配套 |

**关键路径**（自营）：解除异常 → 改照 → 定场地并装修 → 申报食品经营许可（含现场核查）→ 域名 + ICP 备案 → 小程序认证 → 微信支付商户号 → 提审上线。
**触发条件**：ABox 自有场所证照齐、现场可核查；4 家供应商半成品供货协议签署完成。

## 四、123 号令下的「不冲突」论证与残留风险

**结论**：单主体自营 + 半成品供应链**不冲突** 123 号令 —— 号令约束的是**入网商户**（向消费者出餐的店铺），本模式下：

- 向用户出餐的**只有 ABox 一家**，123 号令的「一店一证一地址」「禁止异地代工出餐」「门头名 = 网店名」只对 ABox 自家场所生效；
- 4 家供应商是 **B2B 半成品供货方**，不面向消费者、不开店铺、不进入 123 号令的入网商户管理；
- 集散中心是 ABox 的**加工/打包环节**，不是独立出餐主体 → 现场加工须落在 ABox 持证场所内。

**⚠️ 残留风险（须逐条落实后才算真正不冲突）**：

| # | 残留风险 | 处置 |
| --- | --- | --- |
| 1 | **「4 家各出一菜 → 集散拼一份 ¥25.80」是否等于「异地代工出餐」** | 必须让**最终热食加工（复热/拼装/打包）发生在 ABox 持证场所**；供应商只交付半成品，不做成品出餐 |
| 2 | 集散场地若在供应商处 | 与 §三 冲突（拿证主体不是 ABox）→ **集散/复热须落到 ABox 自有场所** |
| 3 | 半成品供应商是否需持证 | 视其交付形态：**预包装/生制半成品** 与 **熟制半成品** 的证照要求不同，签约前逐家核实 |
| 4 | 门头招牌 | 招牌名须含 **ABox 一盒**（≠「巡礼之年」），与网店名一致 |
| 5 | 数据模型遗留冲突 | ✅ **M4-0 已清零（2026-09-16）**：`ab_distribution_center.supplier_id` → **可空历史字段**；主体 `type` → **历史字段**；`SUPPLIER_TYPE_CONFLICT`(50008) **三处闸门拆除**（号位保留不用）+ **D27 路由删除**；应付结算语义 ✅ M3-9 已转采购应付。**另**：S3 打包任务整条迁运营后台（`GET /admin/packing-tasks` · P39）—— 原判据失效且数据面跨供应商（违反 I1）。详见 `.workbuddy/memory/ref/资质与合规.md` §四 · 《缺陷与陷阱》#58 |
