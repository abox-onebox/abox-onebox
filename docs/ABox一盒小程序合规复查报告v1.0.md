## 二、P0 · 溯源页仍在引导用户去第三方平台 ✅ 已修复

### 实测证据（真发请求，非读代码推断）

接口：`GET /traceability/today?buildingId=1&mealDate=<明日>` —— **免登录**，审核员不需要任何身份即可抓到。

`traceNote` 字段的真实返回值（逐字）：

> 这一盒由 4 家菜品供应商 + 1 个集散中心（集散中心 1（国贸/建外））联合出品。所列出品方均已通过
> 食品经营许可证 · 营业执照 核验。**如果今日套餐不合口味，也可以点进下方店铺，直接点他们的外卖；**
> 用餐有任何问题都可以联系我们协助处理。

同一个响应里的其他命中：

| 项 | 实到值 |
|---|---|
| 第三方平台名 | `美团` · `京东` · `淘宝`（以及 `meituan` / `taobao` / `jd` 三个键名） |
| 第三方平台 URL | **9 条**，形如 `pages/shop/index?shop_id=100001` |
| `takeoutLinks` 字段 | **仍在下发** |

### 为什么这条比昨天那条更严重

1. **它是必然触发，不是"配置后才出现"。** 种子数据里三家供应商**全都配了**外卖链接（共 9 条），
   判据 `dishes.some(d => d.supplier.takeoutLinks.some(l => l.configured))` 恒为真 ⇒ 文案天天显示。
2. **URL 是小程序路径，不是 http 链接。** `pages/shop/index?shop_id=100001` 正是喂给
   `wx.navigateToMiniProgram` 的形态 —— 配合代码里现成的 `TAKEOUT_MINI_PROGRAM_APPID`，
   填一个 appid 就是标准的跨小程序互推，**5.10 命中得比昨天更彻底**。
3. **用户看得见，而且指向不存在的东西。** 前端 `traceability.vue` 第 10、23 行渲染 `data.traceNote`，
   但店铺卡片已经删了 ⇒ 文案说"点进下方店铺"，页面上却没有店铺。既是违规，也是逻辑矛盾。

### 命中条款

| **5.10 互推行为** | 不得为他人 APP/小程序「集中设立跳转」，或为其推荐、推广、提供**协助或便利** | **下架** |
| 5.23.7 | 未经授权不得展示或推荐其他微信小程序 | 下架/整改 |
