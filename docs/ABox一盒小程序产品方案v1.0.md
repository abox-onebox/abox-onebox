## 〇、业务全景

### 0.1 一句话定位

> 办公楼白领"一饭四菜"团餐小程序：每日一款固定套餐、四个供应商联合出品、提前一天预订、次日由团长/楼长协同分发到公司楼下。

### 0.2 五大角色

| 角色 | 形态 | 主要诉求 |
| --- | --- | --- |
| **用户**（C 端员工） | 微信小程序 | 简单下单、看今天吃啥、看配送状态 |
| **团长**（按办公楼） | 小程序内嵌 | 分享链接、收集订单、看佣金 |
| **楼长**（按办公楼） | 小程序内嵌 | 收餐核单、分发到楼层/公司 |
| **商家**（4 家供应商） | Web 后台 | 上架菜品、看订单、接单生产、对账 |
| **平台运营** | Web 后台 | 套餐编排、订单管理、财务结算、数据看板 |

### 0.3 核心业务时序

```
T-1 日 09:00  平台发布次日套餐（4 菜 + 1 米饭，由 4 家供应商各供 1 菜）
T-1 日 09:00–20:00  团长分享链接 / 员工下单 / 支付
T-1 日 20:00  订单截止，统计各菜总份数 → 推送 4 家供应商备料
T-1 日 22:00  订单自动结算 → 用户侧可申请退款（截止前）
T 日 06:00  4 家供应商分别出餐至中央厨房 / 集配点
T 日 10:30  配送团队按办公楼分箱配送
T 日 11:00  楼长签收 → 按公司分发
T 日 11:30  用户取餐
T 日 12:00  团长佣金结算（T+1 到账微信零钱）
T+1 日      平台与 4 家供应商按实际分账比例结算
```

### 0.4 关键业务规则

| 规则 | 说明 |
| --- | --- |
| 套餐规格 | 固定 "1 米饭 + 4 菜"，不支持单点、不支持加菜 |
| 预订窗口 | 必须提前 1 日预订，当日 0 点后不可下单次日（次次日可订） |
| 截止时间 | T-1 日 20:00 统一截单，截单后未支付自动取消 |
| 退款规则 | 截单前全额退；截单后不可退（食材已采购） |
| 团长佣金 | 团长所辖订单总金额 × 10%，T+1 自动结算到微信零钱 |
| 供应商分账 | 平台代收 → T+1 按订单分账到 4 家供应商（微信分账接口） |
| 价格策略 | 套餐统一定价（如 28 元/份），平台抽佣（如 15%）、供应商拿大头 |
| 配送模式 | 平台自建配送团队，按办公楼分箱 |

## 二、各模块核心功能点

### 2.1 用户端核心交互细节

**M01-01 今日套餐展示**

- 默认首页即"明日套餐"（因为用户永远只能订次日）
- 顶部倒计时：`还剩 19:42:13 截单`
- 4 张菜卡横滑，每张：菜品图 + 菜名 + 供应商名 + "由 XX 餐厅出品"
- 米饭固定卡片在最前或最后
- 价格大字展示（¥28.00）
- 一键"立即预订"按钮置底

**M02-01 一键下单**

- 进入下单页：自动带入默认地址（公司+楼层），可改
- 数量步进器（1-20 份）
- 备注过敏信息（选填）
- 提交 → 调起微信支付 → 成功 → 跳订单详情
- 若团长 ID 通过链接带入，订单自动关联团长

**M02-05 订单倒计时**

- 服务端统一下发 `cutoff_at`（T-1 20:00 时间戳）
- 客户端每秒刷新倒计时
- 到点后所有"立即预订"按钮置灰 + 文案"今日预订已截止，欢迎订次次日"

**M03 订单状态机**

```
待支付 ──(30min 未支付/取消)──> 已取消
   │
   ├──(支付成功)──> 待出餐 ──(商家确认)──> 待配送 ──(楼长签收)──> 待取餐 ──(T+1)──> 已完成
   │
   └──(截单前取消)──> 已退款
```

### 2.2 团长端核心交互

**M11-02 明日预订进度**

- 展示明日办公楼内已订总份数（实时刷）
- 按公司分组列表（脱敏手机号）
- 推动按钮："还差 X 份达到起送量"

**M12-03 异常订单**

- 列表展示"待支付"且快到截单时间的订单
- 一键复制发送"还差 30 分钟截单，请尽快支付哦~"话术
- 一键拨打用户手机（脱敏后由后台解密）

**M13-02 提现申请**

- 每日 T+1 自动结算昨日佣金到微信零钱（默认）
- 可累计到一定金额手动提现（≥10 元）
- 提现流水：日期、金额、微信交易号、状态

### 2.3 楼长端核心交互

**M21-03 扫码签收**

- 配送员出示配送单二维码（含配送单 ID + 校验码）
- 楼长扫码 → 校验 → 显示本办公楼总份数 → 确认签收
- 签收后自动触发"分发任务"推送

**M21-04 分发确认**

- 按公司/楼层分组列表
- 楼长可勾选"已发放" → 触发该用户"待取餐"状态
- 未在 T+30min 标记的，发送催促通知

### 2.4 商家端核心交互

**M31-01 今日订单**

- 早上 6:00 自动同步：本平台今日订单 = 本菜被订份数
- 备料清单：菜品 × 份数
- 出餐倒计时（11:00 必须出餐）

**M32-02 上架申请**

- 商家选菜品 → 选希望供应的日期 → 提交申请
- 平台运营审核 → 通过后纳入套餐编排候选池

### 2.5 平台后台核心交互

**M41 套餐编排（最核心运营模块）**

- 日历视图，每天一个"套餐槽位"
- 创建套餐流程：
  1. 选日期
  2. 选 4 个菜档位（肉/素/汤/主食），从供应商菜品库选
  3. 系统自动校验：是否每档至少 1 个供应商候选
  4. 指派 4 家供应商（手动/自动轮询）
  5. 设置价格、限购份数
  6. 一键上架 → 上架时间可定时（如 T-1 09:00）

**M43-01 配送单生成**

- T-1 22:00 定时任务：按办公楼聚合订单 → 生成配送单
- 每张配送单：办公楼、总份数、4 菜各几份、4 家供应商出餐量、配送员
- 同步推送至配送员小程序（独立配送端，本期不含，作为二期）

**M48 财务结算（重头戏）**

- **团长佣金**：每日 02:00 跑批，计算昨日实际完成订单 × 10%，调用微信企业付款到零钱 → 失败重试 3 次 → 人工介入
- **供应商分账**：每订单支付时已用微信分账冻结资金，T+1 02:00 调用分账确认接口，将冻结资金分给 4 家供应商（按约定的分账比例）
- **对账**：每日 04:00 下载微信支付对账文件 → 与本地订单比对 → 差异告警
- **退款**：原路退回用户，供应商侧相应扣减（已分账需调用回退接口）

## 三、关键业务场景专项设计

### 3.1 订单截止时间控制

```
T-1 20:00:00  触发 CronJob：批量将"待支付"订单置为"已取消"
                                触发"出餐通知"推送给 4 家供应商
                                触发"截单战报"推送给团长
                                推送"明日菜单"给订阅用户（次次日预告）
```

- 服务端以 UTC 时间戳统一判定，避免客户端改时间绕过
- 前端倒计时仅做展示，最终以下单接口返回的 `can_order: false` 为准

### 3.2 团长佣金自动结算

| 项 | 规则 |
| --- | --- |
| 计算口径 | 以"实际完成"订单为准（已取消/退款不计入） |
| 计算时点 | T 日订单"已签收"后 |
| 结算时点 | T+1 日 02:00 跑批 |
| 结算方式 | 微信企业付款到零钱 API，自动到账 |
| 异常处理 | 单笔失败 → 重试 3 次（间隔 1h） → 人工工单 |
| 提现规则 | ≥10 元可手动提现；<10 元自动累积到次日 |
| 资金来源 | 平台收入（套餐价 - 食材成本 - 供应商分账 - 配送成本 = 平台毛利，从中支出） |

### 3.3 供应商分账方案

**两种可选模式：**

#### 方案 A：微信支付分账（推荐）

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 用户支付 | JSAPI 支付 | 收款方为平台主体 |
| 冻结资金 | / 不分账，留在平台账户 | T+1 确认分账 |
| 分账 | `profitsharing/orders` | 按 4 家供应商预设比例分账 |
| 分账回退 | `profitsharing/return-requests` | 退款时调用回退 |

- 优势：合规、资金安全、微信官方支持
- 成本：每笔分账 0.1%（微信手续费）
- 限制：需申请"微信支付分账"产品权限（主体为平台，需 4 家供应商成为"分账接收方"）

#### 方案 B：人工月结（备选/初期）

- 平台全额收款，月度结算时线下打款给供应商
- 优势：无需分账接口资质
- 劣势：资金压力大、对账繁琐

**推荐：方案 A**，但需先完成微信支付分账产品签约。

### 3.4 对账与退款

**每日对账：**

```
04:00  下载微信支付对账文件 (.csv)
04:30  与本地订单库逐笔比对
05:00  输出对账差异报告（长款/短款/状态不一致）
05:30  推送告警至运营钉钉群
```

**退款流程：**

```
用户发起退款
   ↓
校验：是否在截单前？是 → 自动退；否 → 转人工
   ↓
调用微信退款 API（refund/domestic/refunds）
   ↓
同步：
   - 若已分账 → 调用分账回退 API 从供应商回退相应金额
   - 若未分账 → 直接从冻结金额扣减
   ↓
更新本地订单状态为"已退款"
   ↓
触发团长佣金回退（按比例扣减次日佣金）
```

## 四、技术选型建议

### 4.1 总览

| 层 | 推荐方案 | 备选 | 理由 |
| --- | --- | --- | --- |
| **小程序前端** | **uni-app (Vue3 + Vite + TypeScript)** | 原生微信小程序、Taro | 一码多端（微信/支付宝/抖音）、生态成熟、上手快 |
