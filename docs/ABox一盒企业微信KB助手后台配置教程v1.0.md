# ABox 一盒 · 企业微信 KB 助手后台配置教程（Windows 版）

> 目标：在企业微信管理后台建一个「自建应用」，拿到 5 个值填进服务器 `.env.prod`，
> 让同事在手机企业微信里给内部助手发消息就能操作后台。
> 本教程只讲**后台怎么点**，不含服务器部署（部署见《发布执行清单》）。

---

## 〇、先搞清楚两件事（避免走错入口）

1. **用浏览器，别用「企业微信」电脑客户端。**
   客户端（桌面版）是拿来聊天的，**不是管理后台**。管理后台只在网页：
   👉 用 Windows 上的 **Chrome 或 Edge** 打开 `https://work.weixin.qq.com/`
2. **你必须是企业管理员**（或该应用有「自建应用」权限的人）。
   普通成员看不到「应用管理 → 创建应用」。

---

## 一、登录管理后台

1. 浏览器打开 `https://work.weixin.qq.com/`
2. 右上角点「**企业登录**」
3. 用**管理员企业微信扫码**（或账号密码）登录
4. 登录后进入管理后台首页（左侧有一排导航：工作台 / 客户联系 / 应用管理 / 我的企业 …）

---

## 二、拿 CorpID（企业ID）→ 填 `WECOM_CORP_ID`

1. 左侧点「**我的企业**」
2. 进入「**企业信息**」页
3. 拉到页面**最底部**，有一行「**企业ID**」（一串 `ww` 开头的字母数字，如 `ww1a2b3c4d5e6f7`）
4. **复制**这串 → 记到你的小本本（或稍后填进 `.env.prod` 的 `WECOM_CORP_ID`）

> ⚠️ 企业ID 是全企业唯一的，和哪个应用无关，只拿一次。

---

## 三、创建自建应用

1. 左侧点「**应用管理**」
2. 进入「**应用**」标签页（默认就在）
3. 页面**往下拉**，找到「**自建**」区域
4. 点「**创建应用**」

填写应用信息：
- **应用logo**：点「上传」选一张图（建议用 ABox 米色 `#F6F0E5` / 暖棕 `#6E5435` 风格图标；没有就先用默认）
- **应用名称**：`ABox一盒内部助手`
- **应用介绍**（可选）：`内部替操作台，企业微信里发指令即可操作后台`
- **可见范围** ⚠️ **很重要**：
  点「选择」→ 勾选**要用这个助手的同事 / 部门**
  （只有这里的人，才会在手机企业微信里看到这个应用、才能给它发消息。
  建议先选**你自己 + 1~2 个测试同事**，跑通后再加人）
5. 点「**创建应用**」

---

## 四、拿 AgentID 和 Secret → 填 `WECOM_AGENT_ID` / `WECOM_SECRET`

创建后会**自动进入应用详情页**，这就是后面要反复回来的地方。

1. 详情页里找「**AgentId**」（一个数字，如 `1000002`）
   → 复制 → `WECOM_AGENT_ID`
2. 详情页里找「**Secret**」那一行，点「**查看**」
   - 会要求管理员**扫码或短信验证**
   - 验证后显示一串字符（如 `aB3cD4eF...`）
   → 复制 → `WECOM_SECRET`

> ⚠️ Secret **只显示这一次**！复制后妥善保存（但**不要进代码、不要发到聊天**，
> 只进服务器 `.env.prod`）。丢了就回这里点「重置」重新生成。

---

## 五、设置接收消息（核心，但先别点保存）

1. 在应用详情页，找「**接收消息**」这一栏 → 点「**设置API接收**」（或「修改」）
2. 弹出配置框，填三项：

   | 字段 | 填什么 | 对应 .env.prod |
   | --- | --- | --- |
   | **URL** | `https://api.xunlizhinian.cn/wecom/kb/callback` | （不用填 env，写死在代码） |
   | **Token** | 点「**随机生成**」或自己写 ≥3 位 | `WECOM_TOKEN` |
   | **EncodingAESKey** | 点「**随机生成**」（43 位） | `WECOM_ENCODING_AES_KEY` |

   > URL 必须是 **https**，且**公网能访问**（企业微信服务器从腾讯侧来访问你的域名，
   > 不是从你本机）。`/wecom/` 路径大小写敏感，必须整段转发（nginx 已加好反代，见下文「常见坑」）。

3. **Token / EncodingAESKey 这俩值，复制下来记好**（它们要原样填进 `.env.prod`）。
4. **先别急着点「保存」** —— 点保存时企业微信会立刻向你的 URL 发 GET 校验，
   **服务端必须先部署好**才能通过（见第六步说明）。
   - 如果你现在就点保存：会提示「URL 超时 / 校验失败」，这是**预期的**，没关系。
   - 把 Token / EncodingAESKey 记下来，关掉弹框也行（重开时你填的值还在）。

---

## 六、把 5 个值交给我，由我方部署后再「保存」

你手里现在有 5 个值：

```
WECOM_CORP_ID       = ww...（第二步企业ID）
WECOM_AGENT_ID      = 1000002（第四步 AgentId）
WECOM_SECRET        = aB3c...（第四步应用Secret）
WECOM_TOKEN         = （第五步框里生成的 Token）
WECOM_ENCODING_AES_KEY = （第五步框里生成的 43 位 EncodingAESKey）
```

把这 5 个值给我（或你直接贴进服务器 `.env.prod`），我方会：
1. 写进 `.env.prod` 并重启 api + admin
2. 跑数据库迁移（建 `ab_wecom_binding` 表）
3. 确认服务起来、回调 URL 公网可达

**部署确认 OK 后，你再回到第五步那个弹框，点「保存」：**
- 企业微信发 GET 校验 → 我们后端验签 + 解密 echostr 返回明文 → 校验通过
- 弹框变「**已启用**」✅ = 这一步成了

> 如果保存仍失败，看《发布执行清单》§6 的排错表（域名 HTTPS 不通 / `/wecom/` 反代没生效 / Token·AESKey 与 `.env` 不一致，是三大主因）。

---

## 七、填 .env.prod（给你方参考，我方代填也行）

服务器 `.env.prod` 追加：

```bash
WECOM_CORP_ID=wwxxxxxxxxxxxxxxxxxx
WECOM_AGENT_ID=1000002
WECOM_SECRET=aB3cD4eFxxxxxxxxxxxxxxxxxxxxxxxxxxxx
WECOM_TOKEN=AbCdEf123456
WECOM_ENCODING_AES_KEY=0123456789abcdefghijklmnopqrstuvwxyzABCDEFG
# 可选：内网基址覆盖（一般不用动，默认 127.0.0.1:3000）
# WECOM_INTERNAL_API_BASE=http://127.0.0.1:3000
```

改完 `.env.prod` 须让容器重读：`docker compose up -d --force-recreate api admin`

## 八、常见坑（Windows 用户最易踩）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 找不到「创建应用」 | 不是管理员 / 用的客户端不是网页后台 | 用浏览器开 work.weixin.qq.com，确认管理员身份 |
| 保存时「URL 超时」 | 域名没上 HTTPS / 公网不通 / 服务没部署 | 确认 `https://api.xunlizhinian.cn/wecom/kb/callback` 浏览器能通（返回空 200 即可） |
| 保存时「URL 校验失败」 | Token / EncodingAESKey 与 `.env.prod` 不一致 | 两边逐字符核对，注意**无空格、区分大小写** |
| 同事在微信里看不到应用 | 「可见范围」没加这个人 | 回第三步把同事加进可见范围 |
| 同事发了消息没回复 | 服务没部署 / 预绑定没做 / 禁发窗口没避开 | 走《发布执行清单》§7 预绑定 + §8 自测 |
| 提示要上传「可信域名校验文件」 | 你点进了「网页授权及 JS-SDK」可信域名 | **消息回调不需要这个**！那是为网页跳转类应用准备的，我们的 bot 纯 API，不用传文件 |

---

## 九、完成后

5 个值给我 → 我方部署 → 你点「保存」看到「已启用」→ 在手机企业微信里找到
「ABox一盒内部助手」发「**帮助**」试一下，应收到指令菜单回复。

> 注：本教程不含任何口令/凭据明文；Secret 只进 `.env.prod`，不进代码、不进聊天。
