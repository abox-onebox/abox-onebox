## 一、为什么差 2.5 个月：资质依赖链

```
【自营 · 单主体】
  营业执照（含餐饮服务）
      └→《食品经营许可证》（区局 · 现场核查 · 北京最快约 10 个工作日）
             └→ 小程序备案（工信部）→ 类目审核 → 提审           ≈ 3–5 周

【第三方平台 · 多商家入驻】
  营业执照（须加「第二类增值电信业务」）
      └→ EDI 许可证（北京市通信管理局 · 法定 60 工作日 / 实务 25–45 工作日）
             │   ⚠️ 前置还须：3 人社保含 1 名计算机 + 商用场地 + 域名 ICP 备案
             │              + 一个功能闭环的交易网站（仅小程序通常不够）
             └→ 网络食品交易第三方平台备案（市级 · EDI 后 30 个工作日内）
                    └→ 类目审核 → 提审                        ≈ 3–4 个月
```

**结论**：EDI 是唯一的长杆。**要快，就必须让"是否构成第三方平台"这个问题的答案变成"否"。**

## 二、⚠️ 快，但不能绕过出餐主体（123 号令红线）

《网络餐饮服务经营者落实食品安全主体责任监督管理规定》（总局令第 **123** 号，**2026-06-01 已施行**）不因你"不是平台"而放松。只要通过网络提供餐饮服务，你就是**入网餐饮服务提供者**，必须满足：

| 要求 | 说明 |
| --- | --- |
| **必须有实体经营门店** | 不能是家庭作坊、虚拟档口 |
| **三地址一致** | **证照地址 = 线上登记地址 = 实际出餐地址** |
| **禁止异地代工出餐** | ❗这条直接约束"4 家供应商各自出餐"的模式 |
| **网店名称 = 实体门面招牌名称** | ❗这条决定你能不能用 ABox 品牌对外 |
| 公示义务 | 主页显著位置持续公示营业执照、食品经营许可证、**门店实拍图**、实际经营地址 |
| 封签义务 | 餐饮食品须包装封口，**开启后无法复原** |
| 无堂食标识 | 不提供堂食须标注 |
| 明厨亮灶 | **倡导**（非强制）；接入则须在主页设链接标识并留存视频 ≥14 天 |
| 食安管理人员 | 须配备食品安全管理人员与制度 |

> **所以"最快"的正解不是"少办事"，而是"让出餐主体唯一化"** —— 只要出餐方唯一，三地址一致、招牌一致、禁止异地代工这三条就同时满足。

## 三、推荐形态：单出餐主体 + 外卖（保留一饭四菜套餐）

### 3.1 形态设计

**把"出餐主体"收敛为一个持证门店，其余供应商降级为食材/半成品供货商（B2B），不面向用户。**

| 角色 | 变更前 | 变更后 |
| --- | --- | --- |
| 出餐主体 | 4 家供应商各自出餐 | **仅 1 个持证门店**（中央厨房，或集散中心升级） |
| 4 家供应商 | 平台"入驻商户" | **食材/半成品供货商**（B2B 供货，不出现在平台上） |
| 集散中心 | 打包场地 | **成为持证出餐主体**（对菜品做组合、摆盘、简单加热 → 属"简单制售"，需在许可证上标注） |
| 用户视角 | 向"某家店"下单 | 向**一个 ABox 门店**下单，一份套餐一个出餐地址 |
| 资质要求 | EDI + 平台备案 | **仅《食品经营许可证》** |

**这样做的三个好处**：
1. 三地址一致、招牌一致、禁止异地代工 —— 一次全部满足
2. **不需要 EDI、不需要平台备案、不需要收付通**，不涉二清
3. 保留"一饭四菜 ¥25.80 套餐"的产品形态与团长分发逻辑，技术侧改动最小

### 3.2 ⚠️ 必须提前解决的一个实操点：门店招牌

123 号令要求**网店名称须与实体门面招牌名称完全一致**。而项目现口径是"集散中心复用合作供应商场地 → 场地费 ¥0"。**如果门店招牌挂的是供应商的名字，而小程序上叫 ABox，就对不上。**

三条解法，按推荐度排序：

| 解法 | 说明 | 代价 |
| --- | --- | --- |
| **A. 与场地方协商挂 ABox 门头** | 在该场地划出独立区域，办 ABox 的门店登记并悬挂 ABox 招牌 | 需场地方同意；可能需办理"一址多照"或独立经营场所证明 |
| **B. 自行租用小面积厨房挂 ABox 招牌** | 最干净，完全自主 | 租金 + 装修 + 设备 + 现场核查 |
| **C. 平台上以该供应商门店名对外** | 招牌天然一致 | ⚠️ ABox 不再是品牌方，品牌与套餐定价逻辑需重构 |

> **建议**：优先问清"集散中心所在地的招牌现在是什么、能不能换成 ABox"。这一件事可能比办证更影响上线时间。

### 3.3 许可证要写对（否则类目过不了）

| 项 | 要求 |
| --- | --- |
| 主体业态 | **餐饮服务经营者（网络经营）** —— 网络经营须括号标注 |
| 经营项目 | **热食类食品制售**（现做盒饭必需）；若涉及组合/摆盘/简单加热，须标注**简单制售** |
| 证照地址 | 必须等于实际出餐地址；一个经营场所一张证 |
| 有效期 | 5 年，到期前 30 日延续 |
| 网络经营报告 | 开展网络经营后 **10 个工作日内**向属地市场监管部门报告 |

**北京办证时效（经验值，以官方为准）**：低风险业态最快 **1 个工作日**；餐饮制售需**现场核查**（核查人员 ≥2 人，查布局、功能分区、消毒冷藏防蝇防鼠设备），**全程最快约 10 个工作日**。昌平区另有"易开店""证照联办"便利化服务，可一窗受理同步办结。

> ⚠️ **⚠️ 警示**：若营业执照经营范围只有"食品销售/预包装食品销售"，**拿不到现制现售**。必须先变更经营范围加"餐饮服务"，再办许可证。

### 3.4 还有一项低成本备案（不阻塞提审）

依《网络食品安全违法行为查处办法》第八条第二款：**通过自建网站（含自建小程序）交易的食品生产经营者**，应在通信主管部门批准后 30 个工作日内，向**所在地市、县级市场监管部门**备案。
- 门槛低：前置只需完成**小程序备案**（**不需要 EDI**；⚠️ 「小程序备案」≠「网站 ICP 备案」，见 §3.5 ③）
- 建议：**与提审并行办理**，不占关键路径
- 近期多地监管已在要求"自建小程序"主动登记（123 号令第三十二条）

### 3.5 ⭐ 有备案就能上架吗 —— 备案、类目、产品形态是三件事

**结论：备案解决"资质"，不解决"产品形态"与"类目选择"。**

> 本节为 2026-09-22 新增。前置事实：用户告知**「仅销售预包装食品备案已完成」**，
> 且产品可能是「合作商家提前做好 + 二次打包」的**预包装形态**（而非现制）。
> **该形态能否成立，取决于《方案 B 适配性核验与二次打包合规判定》里那三个问题的答案** ——
> 本节只回答"假设成立时，上架这一步怎么做"。

#### ① 微信官方明文接受「仅销售预包装食品备案」作为食品类资质 ✅

《微信小店「一级类目-食品饮料」类目管理规则》〔类目资质要求〕原文：

> 食品经营企业需提供《食品经营许可证》；如符合下列例外情形则提供相应证照：
> （1）如属于食品生产企业且仅销售自行生产的食品，则亦可提供《食品生产许可证》；
> （2）**如仅销售预包装食品，则亦可提供《预包装食品销售备案凭证》**。

⇒ 这是**官方规则原文**，不是推测。**备案凭证可用于预包装食品销售类目。**

#### ② 但它的边界是「仅销售预包装食品」，越界即「资质混用」（高频处罚场景）⚠️

| 侧 | 涵盖品类 | 可用资质 |
| --- | --- | --- |
| **预包装食品侧** | 预包装零食、瓶装饮料、酒水、罐装食品、**真空包装食品、常温速食**等**非加工即食**食品 | 《食品经营许可证》**或**《预包装食品销售备案凭证》 |
| **加工食品 / 餐饮熟食侧** | **现做熟食、烘焙糕点、预制菜、加工海鲜、腌制食品、餐饮外卖、即食加工农产品**等**经过二次加工**的食品 | **必须《食品经营许可证》**；⛔ **仅预包装食品备案无效** |

⚠️ 行业资料对这条的总结非常直白：**「很多商家用预包装食品备案上架加工食品，最终被巡检处罚，核心是资质混用。」**

⚠️ 注意：**「预制菜」被列在加工食品侧**，而「真空包装食品 / 常温速食」在预包装侧。
**这条线正好压在本项目的产品形态上** —— 见 §3.2 与《方案 B 适配性核验与二次打包合规判定 v1.0》。

⛔ **不要用"藏起来"的办法**（把加热描述删掉、或类目选成食品销售）。微信审核明确要求"**类目与功能一致，不得隐藏或多次跳转**"；
地方监管的合规提示也明确「公示内容真实准确、**与实际销售的食品保持一致**」。

#### ③ 备案 ≠ 类目审核（两道独立的门）

| | 小程序备案 | 服务类目审核 |
| --- | --- | --- |
| 性质 | **主体资质**（工信部） | **行业资质**（微信） |
| 办理 | 微信公众平台后台 · **免费** | 微信公众平台后台 · **免费** |
| 需要 | 营业执照 + 法人身份证 + 人脸核验 | 行业许可证 / 备案凭证 |
| 时效 | 平台初审 1–2 + 管局终审 **1–20 工作日** | 类目审核 **3–7 工作日** |
| 关系 | **完成备案才能提交代码审核** | **资质不够则该类目加不上** |

#### ⚠️ 一个必须纠正的说法：「小程序备案」≠「网站 ICP 备案」

| | 微信小程序备案 | 网站 ICP 备案 |
| --- | --- | --- |
| 入口 | 微信公众平台【小程序备案】 | 域名服务商 ICP 备案系统 |
| 对象 | 微信平台内运行的小程序 | 独立域名官网 |
| 材料 | 营业执照 + 法人身份证 + 人脸核验 | 域名 + 服务器 + 主体证件 |
| 作用 | 小程序可被搜索、可发布 | 网站可合法对外访问 |

⇒ **只做小程序商城，只需完成"小程序备案" —— 不需要买域名、不需要境内服务器、不需要网站 ICP 备案。**
（"域名 ICP 备案"只在走 **H5 路线**时才需要 —— 见《H5 路线可行性决策备忘 v1.0》。两者**不能互相替代**。）

#### ④ 2026 年备案是硬前置，且存量小程序限期补备案

- **新小程序：「先备案再上线」** —— 未备案无法提交版本审核、平台不提供上架服务
- **存量小程序：限期补备案**（2026-06-30），逾期**限制搜索/分享、逐步关闭功能直至下架**
- ⚠️ 同一主体下有未备案小程序，**会影响该主体其他小程序及相关服务的审核**
- ⚠️ 备案有**每日提交配额**，额度耗尽当日无法提交（次日刷新）—— 别卡在最后一天

⇒ **今天就查旧电商小程序的备案状态**（§四 D1 项已有此条）。

#### ⑤ 类目怎么选（按产品形态二选一，不能混）

| 产品形态 | 应选类目 | 资质 |
| --- | --- | --- |
| **预包装食品（组合包装）销售 + 配送** | 食品销售 / 商家自营-食品 | 《预包装食品销售备案凭证》 |
| 现制 / 加工食品（餐饮服务） | `餐饮服务 → 餐饮服务场所/餐饮服务管理企业` | 《食品经营许可证》（热食类制售） |
| ⛔ 多商家入驻（二期） | `餐饮服务 → 外卖平台` | **《增值电信业务经营许可证》** |

⚠️ 不要用"生活服务-百货"等泛类目替代食品/餐饮类目，必被驳回
⚠️ 2026 年小程序**首次提审通过率不足 60%**，**类目不符是首位驳回原因**

#### ⑥ 上架后仍有一项常驻义务（124 号令）

店铺主页**显著位置持续公示**许可证（或备案信息）**及可查验链接**，且**与实际销售的食品保持一致**。
⇒ 这是**上架前就要有的功能**，不是上线后补。

## 四、最快路径执行表

**关键路径 = 食品经营许可（~10 工作日）→ 小程序备案（平台初审 1–2 + 管局终审 1–20 工作日）→ 类目审核（3–7 工作日）**
（以下工作日为经验值）

| 时点 | 关键路径动作 | 可并行动作 |
| --- | --- | --- |
| D1 | 核对营业执照经营范围是否含"**餐饮服务**"（缺则当日提交变更，1–3 工作日） | ① 核查旧电商小程序**备案状态**是否正常 ② 确认**门店招牌**能否挂 ABox ③ 确认是否已持 EDI（决定二期，不影响一期） |
| D1–D2 | 若已持证：核对许可证**经营项目是否含"热食类食品制售"**、是否标注"网络经营"；缺则申请**变更增项** | — |
| D1–D3 | **启动《食品经营许可证》新办/变更**：经营场所平面布局图、食品安全管理制度、设备清单、全员**健康证** | **并行**：微信企业认证（若未认证，300 元/年，1–5 工作日） |
| D3–D13 | **现场核查**（约 10 个工作日，昌平可走"易开店"） | **并行启动小程序备案（工信部）**：先确认微信认证已完成 |
| D13 | 许可证到手 | 小程序备案预计已完成平台初审，**留意 12381 短信，24 小时内必须核验**（超时重排） |
| D13–D20 | **提交服务类目**：`餐饮服务 → 餐饮服务场所/餐饮服务管理企业`，上传食品经营许可证 | 小程序功能收尾（见 §六）；准备测试账号与审核说明 |
| D20–D25 | 管局终审通过（1–20 工作日，不可加急） | 自建渠道交易备案提交区局 |
| D25–D28 | **类目审核 3–7 工作日** | 灰度发布预案就绪 |
| D28+ | **提审 → 灰度放量** | — |

**⏱ 累计：约 3–5 周**（前提：小程序功能已就绪、材料一次过）

## 五、两期走法（推荐：先把业务跑起来，二期再转平台）

**不要为了"平台身份"把上线推迟 2.5 个月 —— 先把业务跑通，平台化并行推进。**

| | 一期（3–5 周） | 二期（并行 2–3 个月） |
| --- | --- | --- |
| 形态 | 单主体自营外卖 | 引入多商家入驻 |
| 类目 | 餐饮服务场所/管理企业 | **新增** `餐饮服务 → 外卖平台` |
| 新增资质 | — | EDI → 平台备案 → 收付通 + 二级商户进件 |
| 新增义务 | — | 食安总监/食安员、每 6 个月实地复核、每年 1/7 月报省局 |
| 资金 | 单一商户号（不涉二清） | 电商收付通 + 分账 |
| 风险 | 低 | ⚠️ 二清风控的**主体/法人关联**：一旦违规，**同执照下其他商户号（含一期商户号）会被连带限制** |

> ⚠️ **二期的前置提醒**：若二期真的引入多商家入驻，4 家供应商**各自**都要满足"实体门店 + 三地址一致 + 招牌名一致 + 明厨亮灶"，且平台须做 6 个月实地复核。建议在二期立项前先评估这个成本是否值得——很多情况下，**一期的单主体形态直接长期跑下去更划算**。

## 六、提审自检清单（提审前必过一遍）

### 6.1 主流程必须可完整跑通

| # | 检查项 |
| --- | --- |
| 1 | 从进入小程序到下单成功的**全链路无断点**（含 T-1 下单窗口限制提示是否清晰） |
| 2 | **有入口就有内容** —— 无空页面、无"敬请期待"占位（审核最常抓这条） |
| 3 | 支付流程可完成（含退款入口可见） |
| 4 | 截单后不可自助退的规则**在页面明确告知**（属对用户权利的限制，必须事先明示） |
| 5 | 所有页面文案与选择的**服务类目一致**（类目须覆盖全部实际功能） |

### 6.2 账号与说明

| # | 检查项 |
| --- | --- |
| 6 | **准备可用测试账号 + 审核说明文档**（写明入口路径、测试订单号、关键功能位置） |
| 7 | 测试账号**不能依赖真实支付才能看到后续页面**；提供可跳过支付的测试路径或说明 |
| 8 | 客服入口真实可达（审核会抽查致电/留言） |

### 6.3 隐私与账号

| # | 检查项 |
| --- | --- |
| 9 | 后台**用户隐私保护指引已填写**（不填无法调用 `wx.login` / `getUserProfile`） |
| 10 | **账号注销入口已开发**（隐私合规硬要求，缺失不通过） |
| 11 | 隐私政策 + 用户协议页面已上线，内容与实际收集项**一致** |
| 12 | 收集清单与用途逐项对应（openid、昵称头像、手机号仅团长收集、支付信息等） |
| 13 | 声明不面向未成年人并做限制 |

### 6.4 接口权限与敏感能力（易漏）

| # | 检查项 |
| --- | --- |
| 14 | **地理位置**：`wx.getLocation` 需在 `app.json` 配置权限说明、声明 `requiredPrivateInfos`，**且必须在隐私指引中说明用途**（配送地址场景必用，高频驳回点） |
| 15 | 订阅消息模板已申请（订单通知 / 送达提醒） |
| 16 | 手机号获取能力用途说明（团长场景） |
| 17 | **诱导分享检查**：团长推广文案**不得出现"分享得佣金""拉人得钱"类表述** —— 属明确红线，建议全部改为中性表达 |
| 18 | 无外部支付跳转、无引导至小程序外交易 |

### 6.5 资质一致性

| # | 检查项 |
| --- | --- |
| 19 | 所有上传资质的主体名称与小程序主体**逐字一致**（含括号、全半角） |
| 20 | 证照扫描件清晰、无反光、无遮挡、在有效期内 |
| 21 | 门派/门店实拍图、实际经营地址与证照地址一致 |

## 七、灰度发布与回退

| # | 项 |
| --- | --- |
| 1 | **先小比例放量**（限 1 栋楼 / 1 个团长 / 1 个时段），不要全量 |
| 2 | 盯三件事：**支付成功率、下单转化率、退款率**；另盯**截单时间边界**与**送达时效** |
| 3 | **版本回退预案**：保留上一版本代码包 + 一键回退步骤 + 谁有权决定 |
| 4 | **强制更新预案**：后端下发最低版本号，兜底修复严重问题 |
| 5 | 客服话术与应急联系人值班表就绪 |

## 八、无用户充值带来的三项简化

| # | 变化 | 说明 |
| --- | --- | --- |
| 1 | **单用途商业预付卡备案 → 不适用** | 该备案针对"预收资金"（消费者预付）。无充值即无预收资金，从清单移除 |
| 2 | 资金架构更简单 | 单一商户号收款即可，**不涉二清**，无需收付通/分账 |
| 3 | ⚠️ **但请注意两个残留点** | ① 现有"退款退回余额（非原路）"若保留，余额仍是**应退给消费者的钱**，规模大时建议与区商务局确认是否触及备案口径 ② **团长佣金余额属平台对团长的应付款**，不是预收资金，不触发该备案 |
| 4 | ⚠️ **一旦后续开放充值** | 北京市 2026-05-11 施行的办法规定：**预收资金余额达 20 万元**即应向**区商务局**备案。建议产品上先不做充值入口 |

## 九、待确认清单（按对上线时间的影响排序）

| # | 待确认 | 影响 |
| --- | --- | --- |
| 1 | **"外卖平台"是指业务形态还是多商家入驻定性** | 决定 3–5 周 vs 3–4 个月 |
| 2 | **门店招牌能否挂 ABox** / 集散中心场地归属 | 决定能否直接复用现有场地，影响可达数周 |
| 3 | 营业执照经营范围是否含"**餐饮服务**" | 缺项则先变更（1–3 工作日），是首日动作 |
| 4 | 现有/在办《食品经营许可证》**经营项目是否含"热食类食品制售"、是否标注"网络经营"** | 缺项需变更增项，可能再走一次现场核查 |
| 5 | 旧电商小程序**备案状态**是否正常 | 若被限搜需先处理（24–48 小时同步） |
| 6 | 小程序**功能完成度**（隐私指引、注销入口、客服入口是否已开发） | 常见"以为快，卡在这里" |
| 7 | 全员**健康证**是否齐备 | 办证与公示都要 |
| 8 | 是否已持 EDI（仅决定二期，**不影响一期**） | 二期可省 2–3 个月 |
