# ABox 一盒 · 第三方平台路线 · 上线资质与准入执行清单 v1.1

> **文档性质**：平台路线（多商家入驻）下的上线前置条件执行清单，非法律意见。审核规则以微信公众平台后台提示与通信管理局、市场监管部门口径为准。
> **编制日期**：2026-09-16 ｜ **主体**：北京巡礼之年科技有限公司（昌平区）
> **本版说明**：v1.0 在"自营 / 平台"之间未定性。**本版按已裁决的「第三方平台路线」重捋**，并取代 v1.0 中与自营相关的结论。
> **⚠️ 本版最重要的三个结论**：
> 1. **原「按自营定性 → 不涉二清」的资金合规结论作废**。改为平台后，用户付款进平台商户号再结给入驻商户 = **典型二清**，必须改为微信支付「电商收付通」架构。**这是会连带影响主体下其他商户号的硬风险**。
> 2. **平台方责任全套上身**：食品安全总监 + 专职食安员 + 独立食安机构、每 6 个月实地复核入网商户、每年 1/7 月向省级市监局报送、明厨亮灶标识管理、食安封签监督。
> 3. **❗出现一个必须先裁决的模式冲突（§五）**：现行"4 家供应商各出一道菜、集散中心拼成一份 ¥25.80 套餐"的形态，在 123 号令"**一店一证一地址 + 禁止异地代工出餐**"下无法直接成立。

## 二、❗变更一：资金流必须重构（二清风险回归）

### 2.1 为什么

平台路线下，你的资金动作变成了：**用户付款 → 进平台商户号 → 平台扣佣后结给入驻商户**。

这正是央行银办发〔2017〕217 号所定义的**无证经营支付结算业务（二清）**——平台无支付牌照却实质扮演清算机构。判定四要素：**钱过你手 + 你说了算 + 有时间差 + 你管商户**。

原方案之所以能规避，是因为定性为**自营**（平台采购 + 平台销售），供应商款属采购付款、团佣属营销费用。**改为平台后这条论证链断了**——供应商是"入驻商户"，你代收的货款是"别人的钱"。

### 2.2 硬风险（不只是理论）

| 风险 | 说明 |
| --- | --- |
| **主体关联连带** | 若商户号因二清被风控，**同一营业执照下的其他商户号大概率被连带限制** —— **你已有的电商小程序商户号也会被波及** |
| **法人关联** | 法定代表人名下其他商户号受波及，个人在微信支付体系内信用被标记，后续新注册商户号易被"预标记" |
| **处罚三层级** | 交易拦截 → 收款限额（降到每天几百到几千元）→ 关闭收款功能（业务停摆） |
| **定性最重的一档** | "涉嫌从事未开放行业（无牌清算）"申诉难度极大，可能不可恢复 |
| **监管侧** | 没收违法所得 + 罚款 + 通道关停；金额较大涉嫌非法经营刑事责任 |

### 2.3 合规解法（三选一，推荐第一个）

**方案 ① 微信支付「电商收付通」**（推荐）
- 平台入驻微信支付成为**服务商**；4 家供应商各自开通**二级商户号**
- 用户一次支付 → 资金**分别进入各二级商户账户（冻结状态）** → 订单完结后平台发**分账指令**抽佣
- **资金全程不过平台对公账户**，平台只有"指令权"没有"资金权"
- 关键接口能力：二级商户进件 / 合单支付（最多 50 个二级商户）/ 分账 / 补差 / 退款 / 余额提现
- ⚠️ 约束：**默认分账比例上限 30%**（需申请提升）；**分账接收方须为商户号类型，不支持个人** → 团长佣金仍走灵活用工平台，不变
- ⚠️ 前置依赖链：营业执照含增值电信业务 → 域名归公司名下 + ICP 备案 → EDI 许可证 → 微信支付服务商开通 → 电商收付通 → 申请分账权限

**方案 ② 各商户自收（一清到底）**
用户直接付给对应商户号，平台只收佣金/服务费。合规最干净，但用户需多次支付、平台流水不统一，与"团长统一下单分发"的形态冲突大。

**方案 ③ 银行虚拟户 / 持牌分账服务商**
适合跨生态、大额对公。资金在银行监管体系内闭环。成本较高。

### 2.4 必须同步更新的三份材料

1. **资金合规意见书**（原"自营不涉二清"结论作废，重出）
2. **《供应商合作协议》** → 改为**《平台入驻协议》**（性质从采购变入驻，条款全部重写）
3. **技术方案** → 支付链路从"单一商户号收款"改为"收付通 + 分账"，涉及订单、结算、对账、退款全套改造

> ⚠️ **一个反直觉的提醒**：即使你用微信官方"商家转账"功能打款给供应商，**也不能洗白代收清算行为**——转账只是工具，不改变"资金先归集到平台"的事实。必须先改架构。

## 三、❗变更二：平台方责任全套上身

### 3.1 《网络餐饮服务经营者落实食品安全主体责任监督管理规定》（总局令第 123 号，2026-06-01 施行）

| 责任项 | 具体要求 |
| --- | --- |
| 机构与人员 | 设立**独立食品安全管理机构**，配备**食品安全总监 + 专职食品安全员**；主要负责人负总责；每月食品安全调度会议并留纪要 |
| 准入审核 | 对入网商户实行**实名登记**；**通过实地核查等方式做实质性资质审查**（核验证照与实际是否相符）；与**省级市监局数据核验比对**，不符者不得提供服务 |
| 定期复核 | **每 6 个月**核验更新一次入网商户信息 |
| 信息公示管控 | 入网商户网店名须与**实体门面招牌一致**；主页显著位置公示证照、门店实拍、实际经营地址；无堂食标"无堂食"；**平台须在列表页展示"有/无明厨亮灶"标识** |
| 明厨亮灶 | 为商户实施提供技术支持；监控覆盖加工关键环节；**视频留存 ≥14 天** |
| 食安封签 | 监督商户使用**一次性不可逆封签**；未贴/破损订单**及时拦截** |
| 风险管控 | 制定《食品安全风险管控清单》；技术监测 + 实时巡查 + **实地抽查**；每月风险分析会议 |
| 违规处置 | 发现违法立即制止、报告属地市监部门，并采取**限流、下架、关店、黑名单**措施 |
| 信息留存 | 订单交易记录 **≥3 年**；资质审核/复核/巡查/整改/培训/投诉记录 **≥2 年**；配送人员培训记录 **≥2 年** |
| 定期报送 | **每年 1 月、7 月**向省级市监局报送辖区内全部入网商户资质信息 |
| 配送管理 | 对配送人员（含委托第三方配送）开展食品安全培训；需保温/冷藏的须保证配送温度 |

**罚则提示**：故意违法、性质恶劣或造成严重后果的，除单位罚款外，还可对**法定代表人、主要负责人、直接责任人处以上一年度收入 1–10 倍罚款**。

### 3.2 《电子商务法》平台经营者义务（一并适用）

- 平台内经营者**身份核验、登记、建档**，并定期更新
- 向市场监管部门**报送**平台内经营者身份信息
- **首页显著位置持续公示**平台服务协议与交易规则；**修改须提前 7 日公示**
- 商品与服务信息、交易信息**保存 ≥3 年**
- 消费者权益保护与**先行赔付**责任
- 竞价排名须显著标明"广告"
- 不得对平台内经营者施加不合理限制

> **结论**：平台路线下，"合规"不是一个上线前的动作，而是**持续运营成本**（人力 + 制度 + 系统 + 每半年实地复核 + 每年两次报送）。

## 四、❗变更三：入驻商户侧资质与"一店一证一地址"约束

### 4.1 每家入驻商户必须自备（4 家 × 全套）

- 每 6 个月的实地复核记录（照片/签到/复核单）

- 每年 1 月、7 月报送回执

## 五、⭐ 必须先裁决的模式冲突：一份套餐跨 4 家出餐

**这是本次重捋出的最重要问题，建议在花任何资质费用之前先定。**

### 5.1 冲突点

现行模式（据 C9 结算口径）：售价 ¥25.80 一份套餐 = 红烧肉（7.50）+ 时蔬（3.00）+ 卤蛋（1.50）+ 酸辣汤（2.00），供价**逐菜与不同供应商协商**，集散中心拼装后统一配送。

在 123 号令下：

| 号令要求 | 与现行模式的冲突 |
| --- | --- |
| 入网商户必须有实体门店，**证照地址 = 线上店铺地址 = 实际出餐地址** | 用户在平台上向"某一家店"下单，但这份餐的 4 道菜来自 **4 个不同地址** |
| **禁止异地代工出餐** | 一份套餐由 4 家异地出餐、第三地拼装 → 需证明这不构成"异地代工" |
| 不得超许可项目经营 | A 店卖出 B 店制售的菜品，是否落在 A 店许可范围内需确认 |
| 平台须保证商户信息与实际相符 | 平台明知出餐涉及 4 个地址，公示信息如何做到"相符" |

### 5.2 可选出路（供法务评估，非结论）

| 出路 | 说明 | 代价 |
| --- | --- | --- |
| **A. 自建中央厨房** | 所有菜在同一持证地址制作 → 回到"自营 + 单一主体"，平台路线反而不再必要 | 重资产，但合规最干净，且能拿自持"热食类制售" |
| **B. 集散中心持证成为唯一出餐主体** | 供应商降级为**食材/半成品供货商**（供货不面向用户）；集散中心持"热食类食品制售（含简单制售）"作为平台上唯一门店 | 需办证 + 现场核查；跨地址食材运输的温度与运输合规需设计；供应商资质要求随之改变 |
| **C. 拆单：用户分别向各家店铺下单** | 各家各自出餐、各自配送，各自是合规的入网商户 | **失去"一饭四菜套餐"产品形态**，团长集单分发逻辑与配送体验需重做 |
| **D. 套餐由单一供应商出餐** | 4 道菜由一家供应商全包，其余供应商退出该套餐 | 重组供应链，供价与毛利结构重算 |

> **建议**：把 §5.1 的对照表连同"用户在一份订单里到底向谁下单、谁家证照覆盖这份餐"的问题一起交给法务，作为**平台定性意见书**的第二部分。这个问题不定，EDI 与备案的方向都可能选错。

## 六、EDI 许可证办理要点（关键路径最长项）

**全称**：第二类增值电信业务经营许可证（在线数据处理与交易处理业务，业务代码 **B21**）

| 项 | 要求 |
| --- | --- |
| 审批机关 | **北京市通信管理局** |
| 主体 | 必须是**境内有限责任公司/股份公司**（个体户、分公司、合伙企业**不可申请**）→ 公司符合 |
| 注册资本 | 省内（**地网 EDI**）≥ **100 万元**，认缴即可；跨省全国（全网 EDI）≥ **1000 万元**。ABox 仅北京运营 → 地网口径 |
| 经营范围 | 须含「第二类增值电信业务」或「在线数据处理与交易处理业务」；**仅写"电子商务"无效** |
| 人员 | **≥3 名全职员工近 1 个月社保**（岗位覆盖技术运维/信息安全/业务运营），**至少 1 名为计算机专业**；**不接受第三方代缴/挂靠**；社保缴纳单位须与申请企业一致；可能电话回访 |
| 场地 | **商用办公场地**（住宅不可），提供 1 年以上租赁协议或产权证明；**注册地址须与实际经营地址一致**；可能实地核验 |
| 域名与服务器 | **公司名下自有域名 + 已完成 ICP 备案 + 备案主体一致**；服务器部署**中国大陆境内**；SSL、防火墙、备份、数据留存 ≥3 年 |
| **交易系统** | 须具备**商家入驻、订单处理、支付分账、纠纷解决等完整闭环** 的功能证明 → ⚠️ **实务上通常需要一个可访问、功能完备的网站来支撑申报，仅有小程序往往不够**。这是最容易低估的一项前置工作 |
| 股权 | 股权穿透至自然人；**有外资成分（含 VIE）无法直接申请** |
| 材料 | 营业执照、**工商调档版公司章程**（自行打印无效）、股权结构图、法人身份证、社保证明、域名证书、房屋租赁合同、业务说明文档（须清晰描述交易流程与数据流向，忌套模板）、网络与信息安全保障措施 |
| 周期 | 法定 **60 个工作日**；实务材料准备 1–2 周 + 审批约 25–45 工作日 → **总计约 2–3 个月** |
| 费用 | 官方审批**免费**；代办服务费约 ¥5,000–6,000 |
| 后续 | 有效期 **5 年**，到期前 **90 日**续期；**每年需年检**（次年 Q1） |

> **高频驳回点**：① 技术方案/业务逻辑描述不清 ② 社保不足或存在代缴 ③ 网站未备案或功能不完整（缺商家入驻、分账、纠纷处理闭环） ④ 域名备案主体与申请企业不一致 ⑤ 经营范围缺"第二类增值电信业务"。
>
> **✅ 可复用判定**：若旧电商小程序当时是**多商家入驻平台**，公司**可能已持有 EDI**。核实要点：证书业务种类是否含"在线数据处理与交易处理业务（经营类电子商务）"、证书主体与域名是否一致、是否在有效期内且年检正常。

## 七、网络食品交易第三方平台备案办理要点

| 项 | 要求 |
| --- | --- |
| 法规依据 | 《网络食品安全违法行为查处办法》（原食药监总局令第 27 号）第八条第一款 |
| 受理机关 | **北京市市场监督管理局**（**市级，不属于各区市监局业务范围**，申报入口勿选错） |
| **法定前置** | **EDI 许可证**（业务种类含"在线数据处理与交易处理业务"）。⚠️ 北京明确：**拿 ICP 证或 ICP 备案代替 EDI，会被直接退回** |
| 时限 | 取得 EDI 后 **30 个工作日内**必须提交；逾期属违规（可责令改正、警告，拒不改正罚 5,000–3 万元） |
| 材料 | 《网络食品交易第三方平台备案信息登记表》（法人签字加盖公章）、营业执照副本扫描件、**EDI 许可证**、法定代表人 + 食品安全管理员身份证、**域名证书 / 小程序访问地址 / 平台功能截图**、**食品安全管理制度全套**、**入驻商家服务协议范本**、授权委托书（委托办理时） |
| 办理方式 | 全程线上，北京市市场监管局网上政务服务平台，**企业法人账号**（个人账号无申报权限） |
| 办结与公示 | 北京承诺办结 **1 个工作日**（材料有问题会一次告知补正）；完成备案后 **7 个工作日**内监管部门对外公示 |
| 凭证 | 只出**电子备案凭证**，无纸质证书；取得备案号后须在平台首页显著位置公示，接受社会监督 |
| 有效期 | **长期有效，不需年审** |
| 变更 | 备案信息变更或停止服务，须于 10 个工作日内办理变更/注销 |
| 业态代码 | 备案号编码含主体业态位：`1 = 网络食品销售`、`2 = 网络餐饮服务`。⚠️ **若已有"京网食备"备案号，大概率只覆盖"食品销售"，必须先变更增加"网络餐饮服务"业态** |

**高频驳回点**：① 用 ICP 证代替 EDI ② 域名/IP/服务器信息与电信资质不一致 ③ 食品安全管理制度照搬模板、与平台实际业务不匹配 ④ 平台地址无法正常访问 ⑤ EDI 证书主体与公司名称不一致 ⑥ 先上线后补备案。

## 八、微信侧准入 + 接口权限

### 8.1 提审前必须对齐的三件事（本专家核对项）

| # | 对照项 | 本项目情况 |
| --- | --- | --- |
| 1 | **服务类目与实际功能是否一致** | 类目选 `餐饮服务 → 外卖平台`。⚠️ 你的小程序功能不止"点餐+外卖"，还有**团长推广分销、余额提现**；类目须能覆盖实际功能，否则按"类目不符"驳回 |
| 2 | **该类目是否需要额外资质** | 需要 → **网络食品交易第三方平台备案**（2 选 1 之一）。这是本路线的核心材料 |
| 3 | **是否存在需要单独申请的接口权限** | 见 §8.3 |

### 8.2 微信侧提交清单

| 项 | 要点 |
| --- | --- |
| 服务类目 | `餐饮服务 → 外卖平台`。**商业类小程序类目修改次数与数量有限，一次性选全，不要试探性提交** |
| 资质上传 | 网络食品交易第三方平台备案凭证（或网络餐饮服务第三方平台备案） |
| 小程序备案 | **微信认证 ≠ ICP 备案**，两者都要；12381 短信须 **24 小时内**核验，超时重排 |
| 用户隐私保护指引 | 后台必填，不填无法调用 `wx.login` / `getUserProfile` |
| 账号注销入口 | 隐私合规硬要求，缺失不通过 |
| 客服入口 | 真实可达，会抽查 |
| 主体一致性 | 所有资质主体名称须与小程序主体**完全一致**（含括号、全半角） |

### 8.3 接口权限与隐私申报（易漏项）

| 能力 | 申报要点 |
| --- | --- |
| **地理位置 / 地图** | `wx.getLocation` 需在 `app.json` 配置权限说明并声明 `requiredPrivateInfos`，且**必须在隐私指引中说明用途**。配送地址场景必用，属高频驳回点 |
| 手机号获取 | 需企业主体 + 说明用途；团长场景收集手机号须在隐私政策中单列 |
| 订阅消息 | 订单通知/送达提醒需申请模板 |
| 微信支付 | 服务商 + 电商收付通（见 §二） |
| 分享 / 小程序码 | 用于团长推广，须避免"诱导分享"表述（分享得佣金类文案**属明确红线**） |

## 十、平台路线专属驳回原因与改法

| # | 驳回原因 | 改法 |
| --- | --- | --- |
| 1 | 用 ICP 证/ ICP 备案代替 EDI 做平台备案 | **必须 EDI**，北京明确退回 |
| 2 | 先上线后补备案 | 取得 EDI 后 30 个工作日内必须备案 |
| 3 | 类目选「餐饮服务场所」但实为多商户平台 | 按实际功能选 `外卖平台`；类目须覆盖全部功能 |
| 4 | 食品安全管理制度空洞、与业务不匹配 | 制度须贴合真实流程（入驻审核、分账、投诉、下架） |
| 5 | 门店证照地址与出餐地址不一致 | 三地址一致，硬红线 |
| 6 | 网店名与实体门面招牌不一致 | 逐店核对并留存招牌照片 |
| 7 | 无堂食未标注 / 未展示明厨亮灶标识 | 按 123 号令公示要求整改 |
| 8 | 入驻商户资质过期未及时复核 | 6 个月复核机制 + 有效期预警 |
| 9 | 团长推广文案含"分享得佣金"类表述 | 改为中性表达，避免诱导分享 |
| 10 | 平台协议/交易规则未在首页显著位置公示 | 补公示位；修改须提前 7 日公示 |
| 11 | 有入口无内容、流程未跑通 | 提交前跑通完整主流程（下单→支付→分账→退款） |
| 12 | 测试账号不可用 | 准备可用测试账号 + 审核说明 |
| 13 | 主体经营异常 | 前置修复 |
