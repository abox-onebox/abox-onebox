一、只有你能办（卡死项，缺一不能上线）

序事项为什么卡可并行？
1 你办 注册域名 微信支付回调地址必须是公网 HTTPS 域名；小程序后台也要配 request 合法域名。实测：当前 APP_BASE_URL 是裸 IP + HTTP 最先做
2 你办 ICP 备案（腾讯云） 中国大陆服务器绑定域名对外服务必须备案。时间瓶颈：10–20 个工作日，备案没下来就没有 HTTPS 回调 今天启动
3 你办 申请微信支付商户号 需拿到 4 样：商户号 WXPAY_MCH_ID、APIv3 密钥 WXPAY_API_V3_KEY、API 证书序列号 WXPAY_SERIAL_NO、商户私钥文件 apiclient_key.pem。实测这 4 项目前全部为空 与备案并行
4 你办 签发证书 + 开 443 实测：ss -tlnp 无 :443 监听，/etc/letsencrypt 与 certs/ 均不存在 ⇒ 现在整站只有 HTTP 备案 + 解析后
5 你定 资质口径确认（一句话即可） 手册 R9 写「食品经营许可证（热食类制售）未下」，而 2026-10-21 决策记录的是「改为预包装快消品 ⇒ 不需要」。两处口径不一致，涉及小程序类目与支付商户类目，需要你确认当前实际经营形态是哪一种 随时
6 你核 税务非正常户是否已同步解除 工商经营异常已解除；税务是否同步解除未确认。若未解除，会影响对公账户与支付商户号审批 与 3 同步
第 3 项的前置提醒：微信支付商户号审批会看主体资质与经营类目。第 5、6 两项没定清楚就提交申请，被驳回会白白再走一轮周期。

序事项说明

四、资质齐了之后，切 real 的六步（我执行）

  1. 改 .env.prod：PROVIDER_MODE=real，补齐 7 项微信支付与小程序配置
  2. 删掉 ALLOW_MOCK_IN_PROD 这一行（不是置 0 —— 整行删掉最不容易误会）
  3. 商户私钥以文件挂载进容器，不打进镜像层
  4. docker compose up -d 重启（禁止手工 docker restart）
  5. 跑 verify-deploy.sh 确认运行中的产物与本次上线包一致
  6. 双端口 STRICT 冒烟 —— 那两条红（mock 形态 / 逃生开关有值）应当转绿，转绿才允许宣布上线
顺带已核完的安全项（不用你操心）：JWT_SECRET（64 位随机串）、MYSQL_ROOT_PASSWORD 与 DB_PASSWORD 均已换掉占位值；小程序 WX_MINI_APPID / WX_MINI_SECRET 已经配好 —— 缺的只是支付那 4 项。

五、本次回源发现、已订正的两处文档缺陷

  • 支付回调路径写错了：运维手册 §4.2 原写 /api/v1/payments/wxpay/notify，该路由不存在；真源是 /api/v1/pay/notify（payment.controller.ts:57,62）。照抄的后果是「用户已付款但订单永远停在待支付」，且服务端零报错。已订正，错路径以反例形式留在说明里并标注「不存在」。
  • 新增 R14：把「域名 → 备案 → 证书 → 回调地址 → 小程序合法域名」这条不可颠倒的前置链写进手册，附今天的实测证据（无 443、无证书、裸 IP HTTP）。

六、上线前需要知道的三个已知敞口

  • 小额提现：起提不限，金额下限只剩后端 @Min(0.01) ⇒ ¥0.01 也能进审批队列。你已裁定保持现状、运营人工驳回。
  • 一期只允许单 API 实例（R10）：生效业务时刻是进程级单例，多实例会造成「同一分钟下单、一台过一台不过」且两边都不报错。别横向扩容。
  • 未做压测（R5）：500 单/日的性能只在设计里，灰度期观察真实峰值，别用「多开楼」代替压测。
