## 一、结论

| 判断 | 内容 |
| --- | --- |
| 方向 | ✅ **对** —— 微信内 H5 确实**不经过微信小程序的服务类目审核与代码审核** |
| 结论 | ❌ **错** —— 审核没有消失，而是**换成了另外三道门**，且**支付这道门仍在微信手里** |
| 净效果 | H5 比小程序**多过 3 道门槛**，能力**全面降级**，时间**并不更快** |
| 建议 | **主交易链路走小程序 —— 且这已是唯一通路**（第三方渠道已于 2026-09 整体关闭，见 §五）；H5 只用于**不带支付**的展示 / 承接页 |

一句话：**换 H5 不是「绕过审核」，是「换一个审核方」——而且新审核方管的事更多。**

## 二、为什么「H5 免审核」不成立

### 2.1 硬证据：微信内的收钱动作，前置就是一道审核

微信支付官方文档（JSAPI 支付 · 开发接入准备）原文要求：

1. 只有申请 **服务号**、政府或媒体类型的公众号才支持申请 JSAPI 支付权限
2. **未认证的账号无法申请 JSAPI 支付权限**
3. 需 **已备案域名**

即：**在微信内想收钱 → 必须有已认证服务号 + 已备案域名 → 这就是微信审核。**
逃开的只是「小程序审核」这一道，换来的是「公众号认证审核」这一道。

> 补充：不走微信支付也不行。**微信内置浏览器屏蔽支付宝**，微信内没有第二条支付通道。

### 2.2 H5 净多出来的三道门

| # | 门槛 | 办理要点 | 周期 / 成本 |
| --- | --- | --- | --- |
| 1 | **已认证服务号** | 主体须正常；服务号一年可群发 4 次；认证费 300 元/年 | 1–5 工作日 |
| 2 | **域名 ICP 备案 + 境内服务器** | 需域名实名 + 境内主机；北京约 20 工作日 | ⚠️ 另有域名 + 服务器成本 |
| 3 | **业务域名 / JS 接口安全域名 / 网页授权域名配置** | 二者均需 **ICP 备案 + HTTPS + 无重定向链路**，业务域名还需文件校验 | 配置 1–3 天（依赖第 2 项先完成） |

### 2.3 时间上并不更快

| | 小程序（自营） | 微信内 H5 |
| --- | --- | --- |
| 备案环节 | 小程序备案（工信部） | **网站 ICP 备案**（北京约 20 工作日，且需先买域名+服务器） |
| 认证环节 | 小程序企业认证 1–3 天 | 服务号认证 1–5 天（300 元/年） |
| 资质环节 | 食品经营许可证 | 食品经营许可证（**一样要**） |
| 支付环节 | 微信支付商户号 | 微信支付商户号（**一样要**）+ 域名三项配置 |
| **合计** | **3–5 周** | **≈ 1 个月起，且能力降级** |

⚠️ 关键点：**网站 ICP 备案通常比小程序备案更慢**，因为多出「域名实名 + 境内主机采购 + 网站接入商」三个环节。

### 2.4 外链管控是「事后杀手」（H5 独有风险）

微信《外部链接内容管理规范》对 H5 有**过审后的持续拦停权**，这与小程序「过审即稳定」有本质区别：

- **未备案域名在 2026 年几乎无法在微信内访问**（新增 HSTS 强制加密规则）
- 判定输入包含**域名历史黑名单、关联域名、IP 信誉** —— 有历史违规的域名即使整改也可能仍被拦
- **同一域名 1 小时内 50 人以上举报，或单日访问量突增 10 倍以上** → 判定为疑似垃圾/病毒传播，直接触发拦截
- 处置手段：限制链接在微信内直接打开 / 限制域名在微信内的访问 / 停止服务
- 申诉需提供 ICP 备案信息；**重复违规可永久屏蔽**

对外卖这种**高频、集中爆发、被投诉概率高**的业务，「访问量突增 10 倍」恰好是开团当天的正常状态 ——
这不是理论风险，是业务形态自带的触发条件。**域名被拦停 = 业务当天归零，且没有替代入口。**

## 三、能力缺口（外卖场景逐项对照）

| 能力维度 | 微信小程序 | 微信内 H5 | 影响 |
| --- | --- | --- | --- |
| 订单状态推送 | 订阅消息（可申请长期模板） | 仅服务号订阅通知，且需用户逐个授权 | ⛔ 外卖的「备餐/送达」通知失效 |
| 复购入口 | 我的小程序 / 桌面图标 | 只能收藏链接 | ⛔ 高频复购全靠用户记得 |
| 团长分享形态 | 小程序卡片 + 小程序码 | 纯链接，无卡片无码 | ⛔ 分发效率与信任度双降 |
| 定位与地址 | 原生定位，一次授权 | JS-SDK 授权，多一次跳转 | ⚠️ 下单流失 |
| 登录 | 静默免密登录 | 网页授权，**须认证服务号** | ⚠️ 每次进站多一跳 |
| 首屏速度 | 本地缓存，基本秒开 | 每次重新加载 | ⚠️ 午间高峰体验受损 |
| 被拦停风险 | 过审后长期稳定 | 外链规范下可被随时拦停 | ⛔ 单点归零风险 |

**前三项（推送 / 复购入口 / 分享卡片）在 H5 下没有替代方案，而它们恰好是盒饭这门生意的命脉。**

### 技术侧补充（uni-app 的复用边界）

本项目是 uni-app，**一套代码可编译到 H5**，所以「加一个 H5 出口」的成本很低 —— 但不要误以为
「顺手就有」。以下四处**必须另写实现**，不能假设自动可用：

| 能力 | 小程序实现 | H5 需改为 |
| --- | --- | --- |
| 登录 | `uni.login` 静默 | 公众号网页授权（服务号 + 授权域名） |
| 支付 | `uni.requestPayment` | JSAPI 支付（需 openid，依赖服务号） |
| 定位 | `uni.getLocation` | JS-SDK `wx.getLocation`（需 JS 安全域名） |
| 推送 | 订阅消息 | 无原生方案，降级为短信/服务号订阅通知 |

## 四、合规责任不因承载形态改变

⚠️ **换 H5 不会减轻任何一项食安义务** —— 这些来自法规，不来自平台规则：

| 要求 | H5 下是否仍然适用 |
| --- | --- |
| 实体门店（实际加工场所） | ✅ 仍然适用 |
| 证照地址 = 线上地址 = 实际出餐地址 | ✅ 仍然适用 |
| 禁止异地代工出餐 | ✅ 仍然适用 |
| 网店名 = 门面招牌名 | ✅ 仍然适用 |
| 公示证照 + 门店实拍 | ✅ 仍然适用 |
| 食安封签 / 无堂食标识 | ✅ 仍然适用 |
| 《食品经营许可证》含「热食类食品制售 + 网络经营」 | ✅ 仍然适用 |

❗**反而要警惕一个反向风险**：微信对**小程序餐饮类目**有资质前置审查（无证过不了类目审核），
而对普通 H5 **不做餐饮资质前置校验**。这意味着 H5 的「容易上线」**不是合规优势，而是没人替你拦**——
踩红线时你是在被查处时才发现的。**H5 上传得越快，风险暴露得越晚。**

## 五、H5 真正应该用在哪

| 用途 | 需要支付 | 前置条件 | 周期 | 评价 |
| --- | --- | --- | --- | --- |
| 品牌展示 / 菜单预览 / 加群引导 / 快团团落地页 | 否 | 仅 ICP 备案 | 数天–2 周 | ✅ **推荐，立即可做** |
| 团长招募页 / 活动页 / 海报二维码落地 | 否 | 仅 ICP 备案 | 数天 | ✅ **推荐** |
| 小程序被拦停时的兜底承接（引导到群/电话） | 否 | 仅 ICP 备案 | 数天 | ✅ 建议备一份 |
| **交易主链路（下单 + 支付）** | 是 | 服务号 + 备案 + 商户号 + 域名三项 | ≈ 1 个月 | ❌ **不建议**（慢且能力降级） |

### ⚠️ 已废止：原「继续用快团团承接一期交易」建议（2026-09-22 撤销）

> **用户告知**：快团团已不允许上架外卖类产品。原建议（下方「原建议」段）**即日作废**。
> 经核查，**这不是快团团一家的问题** —— 而是主流电商与团购平台对「餐饮制售类」商品的**系统性禁售**。

**核查到的真实边界（比「外卖类」更宽）**

| # | 事实 | 信源依据 |
| --- | --- | --- |
| 1 | 快团团自 2026-01 起成批下架**烘焙类食品**（千层蛋糕 / 面包 / 鲜花饼 / 一口酥等），理由「发布店铺或商品违禁信息」，**客服无法给出恢复方法** | 齐鲁晚报报道（2026-01-15） |
| 2 | 快团团开发主体 = **上海寻梦信息技术有限公司（拼多多旗下）** | 公开工商信息 |
| 3 | **拼多多主站已全面禁售「餐饮制售类」商品**，覆盖**热食类 / 冷食类 / 生食类制售** | 平台治理公告 |
| 4 | **抖音电商**同期发布治理公告，**禁止销售及推广餐饮类型的食品**（菜肴、火锅、烧烤、水果捞、生日蛋糕等） | 抖音电商学习中心 |
| 5 | 快团团 2023-06 曾试点上线**餐饮美食 / 本地生活商品**（上海）—— 该方向现已收回 | 公开报道 |

⇒ **结论：现制 / 制售类餐食在主流电商与团购平台已被系统性禁售，换平台（群接龙 / 有赞 / 微店 / 抖音电商）不是解法。**
「快团团这条路以后都不用考虑了」的判断成立，且依据比单看快团团更硬。

> ⚠️ 核查范围声明：以上为「电商商品」形态的规则。抖音**本地生活（到店 / 团购）**是另一条业务线，
> 本次未核查其餐饮准入，**如需该渠道请单独确认**。

**这对本项目意味着什么**

| 变化 | 影响 |
| --- | --- |
| 一期**没有现成渠道兜底** | 自建小程序从「推荐路径」变成 **唯一通路**，没有 Plan B |
| 「先跑流量、后补资质」彻底不可行 | **上线即必须合规**，缄默期不存在 |
| 反向风险升高 | 平台集体禁售说明监管正在压这一块 ⇒ **裸奔做 H5 的被查风险同步上升**（印证 §四 的反向风险） |

**⚠️ 新暴露的产品需求（124 号令 · 2026-05-20 已施行）**

《网络销售食品安全监督管理办法》（总局令第 **124** 号）要求：入网食品经营者须在**店铺主页显著位置
持续公示**食品生产经营许可证（或备案信息）**及可查验链接** —— 覆盖「私域直播间、**线上小程序**、社群团购」各类场景。

⇒ 这不是提审时贴一次就完事，而是**小程序的常驻功能需求**（长期可见 + 可点击核验）。
⇒ 罚则：使用虚假 / 他人资质入网 → 1–3 万元罚款；情节严重 3–10 万元；造成食安危害后果最高 20 万元；
　 并可对企业主要负责人处**上一年度收入 1–10 倍**罚款。

**⚠️ 直接打到团长体系的风险（《电子商务法》8 年来首次修订 · 草案阶段，尚未生效）**

修订草案把**社交小程序私域电商**（微信小程序 / 社群团购 / 团长分销）列入重点监管类别，明确：

- 「**团长无资质售卖食品**」「**多级分销传销模式**」属重罚场景；平台对团长、分销团队行为负**连带责任**
- **团长 / 群主推广明知有问题的食品 → 承担连带责任**

⇒ 对本项目的两条硬要求：
1. **团长体系必须是单级** —— 团长直接推广拿佣金 OK；**团长再发展下级团长并拿差额 = 多级分销，高风险**。
   需与现行佣金模型（见习 / 正式 / 金牌 / 首席 = 8 / 9 / 10 / 12%）核对层级定义是否只按**个人业绩**晋级。
2. 《团长合作协议》须加入**资质告知 + 食安责任 + 连带责任**条款。

## 六、行动建议

1. **主线不变**：自营小程序（3–5 周）。这是当前唯一同时满足「快」与「能力完整」的路径。
2. **H5 值得做，但定位为「不带支付的展示/承接页」** —— 且 **ICP 备案今天就该启动**：
   备案是长周期项（北京约 20 工作日），且与后续任何形态都不冲突，是纯粹的并行项，不占关键路径。
3. **技术侧**：保留 uni-app 编译到 H5 的能力作为**兜底出口**，但要显式排期「登录/支付/定位/推送」四处 H5 实现，
   不要把它们算作「已具备」。
4. **如果最终仍要 H5 主链路**，第一件要确认的事是：**能不能申请到已认证服务号**（主体须正常、300 元/年、
   1–5 工作日）。这一项拿不到，后面的域名和开发都是白做。
5. ⚠️ **不要用 H5 做「规避审核」的架构决策** —— 一旦被判定为规避（例如在小程序被封后转 H5 继续同一业务），
   域名申诉难度会显著上升，且重复违规可永久屏蔽。
