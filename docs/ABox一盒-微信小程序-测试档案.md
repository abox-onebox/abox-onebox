## 2026-10-26 · 场景#01：X5 幂等键在 Redis 不可达时是否仍然互斥

### 一、结论先行

**X5 缺陷已真实复现**：Redis 不可达时，两个服务实例对**同一个幂等键**都能拿到锁（各返回 `true`），
即「同一笔请求可以在两个实例各执行一次」，而**调用方完全无感知**（不抛错、只在日志留一行 WARN）。

| 项 | 结果 |
|---|---|
| 测试文件 | `abox-onebox/scripts/test-kv-idempotency-degradation.mjs` |
| 运行结果 | **PASS 7 / FAIL 1**（③为红 = 复现的正是缺陷本身） |
| 稳定性 | 连续 3 次运行结果完全一致 |
| 反向验证 | RV1、RV2 **双绿** ⇒ 本测试确实具备发现能力 |
| 是否已挂 npm test 链 | **否**（见「五、遗留」——需祝总决定是否纳入门禁） |

### 二、守的是什么

第四批核实发现的 X5：`kv.service.ts:126-128` 中 `setNx` 的 `catch` **不区分异常类型**，
Redis 连接失败/超时/命令错误一律 → `degraded = true` → 退回**进程内内存 Map**。
该标志运行期**零复位**（7 处置位、唯一 1 处 `false` 是第 27 行字段声明），需重启才能恢复。

**为什么必须跑出来**：幂等键是「同一笔钱不会被扣两次」的最后一道防线，
而它失效时**表面上一切正常**（请求照常成功返回）。只读代码会停在「推断」，跑两个实例才能看见保护是否还在。

### 三、实测明细

| # | 断言 | 结果 | 实况 |
|---|---|---|---|
| ① | Redis 不可达时 `setNx` 不向调用方抛错 | PASS | 静默返回，业务无感 |
| ② | 两个实例都发生降级 | PASS | `A.degraded = B.degraded = true` |
| ③ | **同一幂等键在两实例间仍互斥** | **FAIL（缺陷）** | `A.setNx = true`、`B.setNx = true` |
| ④ | `degraded` 运行期无复位路径 | PASS | 置位 7 处 / 置 false 1 处（仅声明） |
| ⑤ | 降级仅打 WARN 而非 ERROR | PASS | 属于不告警的静默降级 |
| RV1 | 探针有效性：共享存储下第二次被拦 | PASS | 同实例 `true` → `false` |
| RV2 | 修复形态下行为翻转（fail-closed） | PASS | patch 后 `setNx` **抛错** |

> ④ 的「7 处 / 1 处」由本测试独立跑出，与第四批报告人工核实的结果**一致** —— 交叉验证成立。

### 四、反向验证证据（不可省）

- **RV1（探针有效性）**：同一实例连续 `setNx` 同键 → 第一次 `true`、第二次 `false`。
  若这条不绿，说明本测试根本测不出「拦住」，等于没写。
- **RV2（修复形态真跑）**：把 `setNx` 的 `catch { degraded = true; return this.setNx(...) }`
  **整块替换**成 `catch (e) { throw e; }`，写临时副本到同目录（保证 `require('@nestjs/common')` 解析正常），
  require 后真跑 → **抛错**。证明本测试区分得了「有保护」与「没保护」两种形态。
  临时副本已在 `finally` 中删除，事后核对 `dist/common/cache/` 目录干净。

### 五、遗留与建议

1. **修复方向**（与第四批报告一致，推荐第一项）：
   - 推荐：**改成 fail-closed** —— Redis 驱动下 `setNx` 抛错直接向上抛，与项目自己在队列上的口径统一
   - 次选：保留降级但加**后台探活**，恢复后把 `degraded` 复位
   - 最小：至少把日志升级为 `ERROR` 并接入告警
2. **修复后如何验收**：直接跑本测试，③ 应从 FAIL 转 PASS（此时 ③ 的失败原因会变成「Redis 不可达时抛错」，
   需同步把①的预期改为「抛错」——修复后应更新断言语义，而不是让测试恒绿）。
3. **未纳入门禁的原因**：项目 `scripts.test` 链为 `build:shared && pnpm -r test`，
   且已有 35 道门禁（`gate.mjs`）。贸然挂入可能影响既有门禁稳定性，**是否纳入请祝总决定**。
   当前为独立可跑：`node abox-onebox/scripts/test-kv-idempotency-degradation.mjs`。
